
# GreenMate 기능 요구사항

## 1. 요구사항 표기

- MUST: 반드시 구현해야 하는 기능
- SHOULD: 가능하면 구현할 기능
- COULD: 시간 여유가 있을 때 구현할 기능

## 2. 기능 목록

### FR-001. 행사 계획 입력

**우선순위:** MUST

사용자는 자연어로 행사 계획을 입력할 수 있어야 한다.

예시:

> 학과 학생 30명이 가평으로 1박 2일 MT를 가려고 해요.

**수집해야 하는 정보**

- 행사 유형
- 목적지
- 참가 인원
- 행사 기간
- 이동수단
- 왕복 이동거리
- 식사 계획
- 숙박 계획
- 소모품 계획
- 예산
- 선호사항
- 제외 항목

**완료 조건**

- 사용자의 자연어 입력이 채팅 화면에 표시된다.
- AI가 필요한 정보를 추출한다.
- 누락된 필수 정보가 있으면 추가 질문을 한다.

### FR-002. 행사 계획 구조화

**우선순위:** MUST

AI가 대화 내용을 구조화된 Plan 객체로 변환한다.

**완료 조건**

- 구조화된 계획이 프론트엔드에 전달된다.
- 사용자가 계획 내용을 확인할 수 있다.
- 누락 필드가 명확하게 표시된다.
- 구조화되지 않은 값은 임의로 확정하지 않는다.

### FR-003. 탄소 및 비용 계산

**우선순위:** MUST

Python 계산 모듈이 카테고리별 탄소배출량과 비용을 계산한다.

**완료 조건**

- 카테고리별 결과가 계산된다.
- 전체 합계가 계산된다.
- 계산에 사용한 단위와 계수가 추적 가능하다.
- 계산 결과는 LLM의 임의 생성값이 아니다.

### FR-004. Hotspot 분석

**우선순위:** MUST

행사 계획에서 탄소배출량이 높은 카테고리를 식별한다.

**기본 규칙**

- 배출량 상위 2개 카테고리를 기본 Hotspot으로 선정한다.
- 3위 카테고리의 배출 비중이 전체의 10% 이상이면 포함한다.

### FR-005. 대안 생성

**우선순위:** MUST

현재 계획의 카테고리별 대안을 생성한다.

**대안 조건**

- 현재 선택과 동일한 항목은 후보에서 제외한다.
- 예산 조건을 검증한다.
- 참가 인원 및 수용 인원을 검증한다.
- 이동거리 및 접근성 조건을 검증한다.
- 사용자가 제외한 항목을 사용하지 않는다.

### FR-006. 대안 비교

**우선순위:** MUST

현재안과 대안 A/B/C를 동일한 기준으로 비교한다.

**표시 항목**

- 총 탄소배출량
- 총비용
- 탄소감축률
- 비용 차이
- 변경된 카테고리
- 제약조건 충족 여부
- 대안의 설명

### FR-007. 최종 추천

**우선순위:** MUST

LLM이 계산 결과를 바탕으로 추천 이유를 설명한다.

**주의사항**

- 추천 이유는 계산 결과와 검증 결과를 기반으로 한다.
- 비용과 탄소 수치를 새로 생성하지 않는다.
- 사용자의 우선순위를 고려한다.
- 조건을 충족하지 못한 대안을 추천하지 않는다.

### FR-008. 결과 시각화

**우선순위:** MUST

결과 페이지에서 다음 정보를 시각화한다.

- 카테고리별 탄소배출 비중
- 현재안과 대안 비교
- 탄소감축률
- 비용 차이
- 추천 대안

### FR-009. 오류 처리

**우선순위:** MUST

다음 상황에 적절한 오류 메시지를 제공한다.

- 필수 입력 누락
- 잘못된 참가 인원
- 음수 비용 또는 거리
- 존재하지 않는 카탈로그 항목
- API 통신 실패
- LLM 응답 실패
- 계산 데이터 부족

## 3. 비기능 요구사항

### NFR-001. 신뢰성

계산 결과는 동일한 입력에 대해 재현 가능해야 한다.

### NFR-002. 보안

API 키와 민감한 설정값을 클라이언트 코드에 노출하지 않는다.

### NFR-003. 유지보수성

계산 로직, API, UI를 분리하여 수정할 수 있어야 한다.

### NFR-004. 사용성

사용자는 복잡한 환경 데이터를 직접 입력하지 않아도
대화형 인터페이스를 통해 계획을 작성할 수 있어야 한다.
